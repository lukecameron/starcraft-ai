# UAlbertaBot native ARM64 port

This port builds the full normal gameplay source from `davechurchill/ualbertabot` revision `558899d8793456f4a6ec4196efbb5235552e24db` as an in-process BWAPI module. The repository is MIT licensed; its notice is copied to `ports/ualbertabot/LICENSE.md`.

The active 2021 bot no longer uses BWTA. BOSS and SparCraft are bundled in the pinned repository and are compiled into the module. The CMake source set follows the Visual Studio gameplay targets and excludes standalone mains, experiments, GUI utilities, and the stale CommandCenter `UnitInfoManager.cpp`; no strategy or gameplay module is disabled.

Run `scripts/build_ualbertabot.sh`. It enforces the UAlbertaBot, OpenBW BWAPI, and official BWAPI revisions, rejects dirty or untracked BWAPI headers, rejects staged or unstaged bot changes outside the canonical patch, rejects ignored or untracked files in all compiled source roots, pins `/usr/bin/clang++`, builds with at most four jobs, and writes `build/ualbertabot/UAlbertaBot.dylib.build.json`. All 115 module translation units also compile against official BWAPI 4.4 headers at revision `7687da8abc4726f8366401f11ab648d421385793`; the runtime module links the project OpenBW BWAPI revision `48124ba8ed1b4d52b3dfd52acbaf34afb9a37fe2`.

The portability patch changes only the module adapter and compiler incompatibilities: portable time and formatting APIs, slash-separated includes, temporary iterator/value bindings, the BOSS BWAPI constructor guard, and a missing `<thread>` include. Windows retains `localtime_s` and `__declspec(dllexport)`; POSIX uses `localtime_r` and default symbol visibility. BOSS and SparCraft initialization formerly performed by the client executable is performed once by the module factory. The upstream full configuration is copied unchanged to `ports/ualbertabot/UAlbertaBot_Config.txt`; it keeps Complete Map Information disabled and SparCraft, BOSS search, scouting, combat, strategy IO, and normal build orders enabled. The build stages the immutable file at `build/ualbertabot/AI/UAlbertaBot_Config.txt`, records it under `ai_files` in the sidecar, and the match runner copies and verifies it as `bwapi-data/AI/UAlbertaBot_Config.txt`. Without the port macro, the original Visual Studio path remains `UAlbertaBot_Config.txt`.

Passive result instrumentation writes `bwapi-data/write/diagnostic.json` and the runner-provided `MATCH_RESULT_PATH`. It observes only the bot's own units and records frame count, winner, ended state, LF3, workers, combat units, and production buildings.

The first cross-race game is `artifacts/runs/20260920T023120-3a7f34fec974/game-0001/manifest.json`: UAlbertaBot Protoss versus ZZZKBot Zerg on Benzene. It completed with verified opposing results in 3.65 seconds at frame 9,582. UAlbertaBot won with 17 workers, 15 combat units, and four production buildings; ZZZKBot lost at frame 9,551. Both reported LF3, both processes exited zero, and both replays were archived. UAlbertaBot plus OpenBW peaked at 50,921,472 bytes RSS. This proves local compatibility and normal gameplay, not strength equivalence to a historical ladder binary.
