# Kestrel v2 build-reservation probe plan

- Registered: `2026-09-20T06:04:40Z`, before any Kestrel v2 match was launched.
- Observed problem: the v0 replay showed 55 pylon/gateway build commands and no combat-unit production. Source review found that `assignEconomy` gave a gather command to the selected builder while it was walking to an accepted build site. V1 throttled repeats but did not reserve that traveling worker and was canceled without a game.
- Change: reserve the selected builder from economy and scouting commands until the building count increases or the 240-frame pending interval expires. While any construction order is pending, do not plan another building; this makes pending pylons part of supply planning. On expiry, reuse the reserved worker for one bounded retry. The opening and combat policy are unchanged.
- Candidate: frozen Kestrel v2 SHA-256 `144d01bc11e64dfdb37113f0e8f79d397846c09373331244ca6563ca8e6d4495`; combined source identity `8ad1044064ab9b8f8bf2511ed5e7f5c97bd63f8c595cfab35559c0263ac68a92`.
- Primary scenario: repeat the exact v0 scenario—Kestrel Protoss player 1 versus WorkerRush Zerg player 2, Benzene, engine seed `6101`, LF3, empty learning state, 120-second wall cap—to test the diagnosed order cancellation on the same trajectory.
- Execution: one attempt after the lead grants a game window. Preserve every result, log, telemetry record, and replay. Do not retry or change the seed after observing it.
- Compatibility gate: both launchers exit zero, terminal callbacks are opposing, no state-hash mismatch appears, and both replay files parse with `screp`.
- Original behavior gate retained: replay or telemetry must show continued probe economy, at least one completed pylon and gateway, production of at least one zealot or dragoon, a scouting or combat movement/attack command beyond the starting base, and no wrong-race production. Missing or ambiguous replay visibility remains inconclusive.
- Fix-specific gate: accepted pylon plus gateway build commands must be at most 12, compared with v0's 55. Inspect their frames and unit tags to verify bounded retries and ensure the reserved worker is not issued a gather command between an accepted build order and either observed construction or its registered retry interval.
- Early-death interpretation: if WorkerRush kills the base before a combat unit can reasonably complete, this primary attempt still fails the original behavior gate. A paced-opponent lifecycle check may then be registered separately to distinguish early defense weakness from a persistent production stall; it will not replace or weaken this result.
- Performance characterization: report whole-match durable throughput and Kestrel callback CPU/p99/max, without treating this short fixture as representative late-game performance.
- Decision: only a compatibility and behavior pass permits a later strength probe. A loss alone is not a rejection, and a win is not a strength or promotion claim.
