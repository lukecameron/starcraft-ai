# Kestrel v5 command-state probe plan

- Registered: `2026-09-20T06:14:42Z`, before any Kestrel v5 game was launched.
- Observed problem: v4 rejected 14 of 77 attempted commands against ZZZK and 621 of 876 against UAlbertaBot. The Terran replay retained 135 accepted `Attack1` orders, showing that public `getOrderTarget()` was not a sufficient record of the bot's last request.
- Change: retain per-owned-unit public IDs for the last requested visible enemy, command frame, and acceptance result. A target change is issued immediately; the same successfully requested target is refreshed only after 96 frames; a rejected request may retry after 24 frames; and the record is removed when no visible legal target remains. This changes command scheduling only. Opening, production, target selection, and construction logic match v4.
- Candidate: frozen Kestrel v5 SHA-256 `eec8734a731d3184b002f069dd1356e995bc9a9422762bd5a8bd488f51655f89`; combined source identity `3e8167c8d2bbbb4c200faf923fa4205593c83eca19a0eee1a36f754e64be9272`.
- Fixed serial schedule, one attempt per row and no retries: repeat v4's two rows exactly—(1) Kestrel Protoss player 1 versus frozen ZZZKBot Zerg on Benzene, engine seed `6103`; (2) Kestrel Protoss player 1 versus frozen UAlbertaBot Terran on Destination, engine seed `6104`. LF3, empty learning state, 120-second wall cap each.
- Reproducibility limit: engine initialization and slots are controlled, but these opponents do not expose controlled bot RNG in this schedule and address/order effects may change full trajectories. Treat comparisons as matched inputs rather than deterministic command streams.
- Infrastructure and behavior guard: every game has zero launcher exits, opposing terminal callbacks, no state-hash mismatch, two `screp`-readable replays, at least 384 durable frames per wall second, at least eight probes, a pylon, a gateway, a zealot or dragoon, scouting and post-production combat, and no wrong-race production.
- Primary command gate: each v5 game's rejected-command fraction is lower than its corresponding v4 result (18.2% ZZZK; 70.9% UAlbertaBot), and UAlbertaBot rejected-command fraction is below 25%. Its accepted `Attack1` count must also be below v4's 135 unless a longer trajectory has proportionally more combat frames; report raw and per-1,000-combat-frame values if that exception is relevant.
- Construction guard: report pylon plus gateway build commands and unit maxima. No change in construction behavior is expected from v4.
- Strength interpretation: report outcomes descriptively. Two matched-input games cannot estimate Elo or justify strength promotion.
- Decision: passing all gates makes v5 the initial runnable command-clean baseline for a later strategy experiment. Failure returns to replay/source diagnosis; no automatic wider batch follows.
