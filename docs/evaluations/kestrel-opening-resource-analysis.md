# Kestrel opening resource and pending-Pylon analysis

The retained v7 diagnostic does not establish that changing the first-Gateway threshold from supply 18 to 16 would be inert. Snapshots are 120 frames apart, so an affordable intermediate frame could be missed. It does show that the pending Pylon and Probe spending are earlier constraints that must be resolved before a threshold experiment is interpretable.

The first Pylon build is accepted at bot frame 942 and replay frame 944 for tile `(111,15)`. A Probe train is then accepted at bot frame 972. At snapshot 960 Kestrel has 100 minerals; by 1,080 it has 74. The builder remains near the mineral line with `PlaceBuilding`: `(3988,523)` at 960, `(3988,524)` at 1,080, and `(3979,525)` at 1,200. At 1,200 the public mineral count is 106, so the trace contains at least one affordable checkpoint while the first order is still stale and the worker has not moved toward the target.

A second Probe is accepted at frame 1,278, after which minerals are 88 at snapshot 1,320. The bot retries the Pylon at frame 1,428/replay frame 1,430. The retry uses a different Probe but the exact same tile `(111,15)`. By snapshot 1,440 that worker is moving near `(3681,500)` with `PlaceBuilding`. Minerals fall from 120 at 1,440 to 36 at 1,560, consistent with the Pylon cost being charged after the retry; the worker then returns to minerals. Supply capacity rises from 18 to 34 between snapshots 1,920 and 2,040.

This evidence supports a specific sequence: an accepted build command does not reserve its mineral cost; later Probe training can consume those minerals before the builder starts. The first Pylon order then remains stale even after minerals recover above 100 at the sampled 1,200 frame. Reissuing the same target with another worker starts construction. The trace cannot distinguish whether the stale order is solely caused by transient resource loss, an OpenBW/BWAPI order behavior, or both. It does rule out a changed target as the retry's explanation.

Supply reaches 16 by snapshot 1,080, but observed minerals are only 74 at 1,080 and 106 at 1,200. Supply reaches 18 by 1,320; observed minerals are 88, 120, 36, 60, 116, and 172 through frame 1,920. Another Probe train at 1,986 competes before the first Gateway is accepted at 2,058. Because intermediate values are unobserved, the calibrated conclusion is: **there is no observed supply-16 frame with 150 minerals, so a threshold-only improvement is unsupported, not proven impossible.**

The next decision should investigate pending-build resource protection before another strategic threshold. The smallest preregisterable change is to prevent new Probe training while an accepted Pylon order has not yet produced a current Pylon, retaining the existing bounded retry and all Gateway thresholds. The mechanism bar should require the first accepted Pylon to become current without a second accepted Pylon command and measure the first-Gateway start as a consequence. This isolates resource/order reliability from first- or second-Gateway strategy; only after that result should a supply-16 Gateway threshold be reconsidered.
